# Open Bids — review desk

## Purpose and user tasks
Track RFQ/RFP opportunities before they enter Proposals. Users inspect the service and client, check submission deadlines and source documents, keep bid details current, then obtain an admin decision before forwarding the bid. Deleted mode is a recovery surface, not a second review queue.

## Information and action priorities
Bid identity, service, deadline and approval state are the first scanning sequence. Anticipated value and the source PDF support the decision. Client, web link, approver and notes remain available; lower-priority reference columns can be revealed through the existing Columns control. Approval and rejection must retain their existing admin gate. Moving to Proposals must retain its approval requirement.

## Organization
A compact review-desk orientation explains the workflow and current access. The existing searchable/filterable/resizable register is preserved, with deadline and approval moved ahead of reference data. Approval actions and the forward action gain visible labels; a one-click Details button removes reliance on double-click. A visible prerequisite explains a disabled forward action. Long service labels, names, document names and notes wrap instead of clipping. Destructive actions stay in the overflow menu.

## Shared design system
Use the master cool-white/graphite surfaces, cobalt selection, restrained translucent chrome and opaque records. Status is always named and icon-supported. Feedback is limited to hover/focus transitions and one subtle panel entrance, disabled for reduced motion. Small-screen actions have 44px targets; wide register scrolling stays inside the existing table container.

## Preservation and verification
No changes to mutations, approval rules, due-date calculations, sorting/filtering, exports, document upload/open/remove handlers, deleted recovery handlers or data. Parent performs integrated local browser verification; this owner checks source compilation and scoped diff.
